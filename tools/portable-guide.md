# AI Security Guard - 演示程序运行说明

这是一个**开箱即用**的演示程序。不需要安装 Java、Maven 或任何开发工具。

---

## 一、怎么运行

**1. 完整解压**

把收到的压缩包**完整解压**到一个文件夹（比如桌面上的 `AI Security Guard`）。

> ⚠️ 不要在压缩包里直接双击运行。必须先解压。

**2. 配置 API Key（只需做一次）**

演示需要一个 DeepSeek API Key——AI 智能体用它来做决策。

1. 打开 https://platform.deepseek.com
2. 注册 / 登录，进入 **API Keys** 页面
3. 创建一个 Key（形如 `sk-xxxxxxxxxxxx`）
4. 用记事本打开文件夹里的 **`apikey.txt`**，把 Key 粘贴进去，保存

> Key 是保密的。不要截图，不要发给别人。

**3. 双击 `start.cmd`**

会弹出一个黑色窗口，显示：

```
   AI Security Guard
   ==============================================================

   正在启动，请稍候（约 5 秒）...

   启动完成后，请打开浏览器访问：

       http://127.0.0.1:8080
```

**4. 打开浏览器**

地址栏输入：

```
http://127.0.0.1:8080
```

看到深色的「AI Security Guard」页面就成功了。

---

## 二、演示时怎么操作

页面有四个标签页：**Overview / Investigation / Approval / Audit**。

推荐按这个顺序演示（约 4–5 分钟）：

### 第 1 步：发起调查

**Overview** 页 → 下拉框保持 `Confirmed vulnerable` → 点 **`Investigate`**

> ⏱ **会出现橙色进度条，等 5–8 秒。** 这是真的在调用 AI，不是卡住。

### 第 2 步：展示 AI 的推理

自动跳到 **Investigation** 页。这里显示：

- **四条决策**，每条都有 AI 自己写的**理由**（`why` 那一行）
- **证据链**：注意扫描器的可靠度是 **MEDIUM**（只是"声称"），运行时版本是 **HIGH**（真的读了）
- **结论**：`CONFIRMED_VULNERABLE` / `P0` / `C0` / `A2`

**这是整个演示最重要的部分** —— 这些工具调用顺序不是预先写死的，是 AI 根据"还缺什么证据"自己选的。

### 第 3 步：人工审批（差异化亮点）

Investigation 页底部 → 点红色按钮 **`Review remediation proposal`**

在 **Approval** 页：

1. 在输入框填一个名字（比如 `chris.selby`）
2. 点 **`Approve & execute`**

会看到：备份 → 执行修复 → **三项独立验证全部 PASS** → `RESOLVED`

> 关键点：**不填名字点批准会被拒绝**。一个无法归属到人的批准不是批准。

### 第 4 步：它不盲从扫描器

**Overview** 页 → 点 **`Clear all cases`** → 下拉框换成 **`Not affected`** → 点 `Investigate`

> AI 只调了**一两个**能力就停手了，判定 `NOT_AFFECTED`，不提议任何动作，不请求审批。
>
> 这证明它是**证据驱动**的，不是在跑固定流程。

### 第 5 步：矛盾时拒绝乱猜

**Overview** 页 → `Clear all cases` → 换成 **`Evidence conflict`** → `Investigate`

> 扫描器明确说"是 2.4.49"，实际跑的是 2.4.58，两者矛盾。
>
> AI 说"**这个矛盾不能靠推理了结**"，于是调用独立验证 —— 验证结果是 `INCONCLUSIVE`。
>
> 最终 `UNDETERMINED` / 优先级**留空** / `C3` / 升级人工 / 自动修复被阻断。
>
> 优先级留空是有意的：AI 拒绝下结论，所以也拒绝说"多急"。

### 第 6 步：审计追踪

**Audit** 页 → 点 **`Verify chain`**

> 显示 `audit chain intact across N events`。
>
> 每条记录用 SHA-256 哈希链环环相扣，任何一条被改动，它之后的全部失效。

## 三、常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 双击 `start.cmd` 一闪而过 | 压缩包没解压 | 完整解压后再运行 |
| 提示"还没有配置 DeepSeek API Key" | `apikey.txt` 是空的 | 按上面第 2 步填入 Key |
| 提示"端口 8080 已被占用" | 上次没关干净 | 按提示执行 `taskkill /F /IM java.exe` |
| 浏览器打不开页面 | 程序还没启动完 | 等黑窗口出现启动完成提示再刷新 |
| 页面全白 | 浏览器缓存 | 按 `Ctrl + F5` 强制刷新 |
| 点 Investigate 很久没反应 | 网络问题或 Key 无效 | 超过 30 秒说明有问题，检查网络和 Key |

## 四、演示时最好说清楚的事

这些是这套系统的**真实边界**。主动说出来，比被问到更好：

- **工具是模拟的**：目标主机是内存里模拟的，不是真的在扫描一台服务器。
  但工具接口是真实的，换成真工具即可接入。
- **数据不持久化**：关掉程序后案件记录就没了。
- **界面没有登录认证**：批准人名字是手输的，不是身份认证过的。
- **测试集是合成的**：覆盖了 27 个场景，但只有 1 个 CVE。

程序**只绑定在本机**（127.0.0.1），局域网内其他电脑访问不到。这是有意的——
因为界面上的"批准"按钮可以真的批准一次修复动作。

## 五、给讲述者的一句话总结

> 扫描器报告不等于确认漏洞。这个 AI 智能体自己决定去查什么证据、得出结论、
> 并且**提议**修复——但它**无权执行**。任何有后果的动作都必须由人批准，
> 而且这是由运行时强制保证的，不是靠提示词请求模型配合。
>
> 我们不是声称 AI 永远正确。我们声称的是：**当 AI 判断错的时候，系统仍然是安全的**——
> 什么都不会被执行，没有虚假的确定性被记录，而且会有人被叫来。
